## 2. 다음 작업 (순서대로)

### ① PC 웹: 컨텐츠 툿을 텍스트 대신 '컨텐츠 화면 UI'로 보여 주기 ← **1차 완료 (2026-10-14)**

> 된 것: 시스템 툿마다 `GameEvent`(그 순간 상태)를 저장 → `REST::StatusSerializer#game_card` → 웹 `ContentCard` 가 본문 위에 카드
> (참가자·소속 문장·차례/결과 배지, 젤리빈 봉지·먹은 맛, 곱스톤 진행 막대·이번 투구, 결투 HP 하트·두 주문·승자, 물약 재료·정답 수 점, 퀴디치 점수·스니치 확률, 수업 등급).
> 진행 중인 판의 최신 툿이면 내 차례 버튼(수락/거절, 먹기, 약·중·강, 결투·퀴디치는 DM) → 누르면 답장 창에 `@시스템 [명령어]` 가 채워진다.
> 각 Kinds 에 `card_data` / `card_actions`, 공개된 마지막 결과는 state 의 `last_*` 로 남긴다. 남은 것: 컨텐츠 진행 화면(3번), 토너먼트·점수 지급 카드.

**요청**: 앱에서는 지금처럼 툿 텍스트(멘션 알림)로 진행. **PC 웹에서는** 시스템 툿을 줄글 대신 컨텐츠 화면으로 보여 준다.

**설계**

1. **툿에 컨텐츠 데이터 붙이기**
   - 새 테이블 `game_events` (status_id, game_session_id, event 종류, payload jsonb).
     `Game::Poster` 가 시스템 툿을 올릴 때 그 순간의 컨텐츠 상태를 같이 저장한다.
     (예: 결투 턴 결과 → 두 사람 이름·소속·선택한 주문·HP, 젤리빈 → 남은 개수·먹은 맛, 물약 → 재료·턴별 정답/순서 틀림 수 …)
   - `REST::StatusSerializer` 에 `game_card` 필드 추가 (시스템 계정 툿에만). 앱은 모르는 필드를 무시하니 앱은 그대로 텍스트.
   - DM 으로 받은 비밀 선택(주문·조합·경로)은 카드에 넣지 않는다 (공개 결과만).

2. **웹 타임라인/스레드에서 카드로 그리기**
   - `Status` 컴포넌트에서 `status.game_card` 가 있으면 본문 대신 `<ContentCard>` 를 그린다. "텍스트로 보기" 토글로 원문도 볼 수 있게.
   - 카드 종류 (해리포터 톤, 시스템 화면과 같은 양피지·금박·소속 문장 스타일 재사용):
     | 컨텐츠 | 카드 |
     |---|---|
     | 신청 | 두 사람 문장 + "vs", 남은 수락 시간, (웹에서) **[수락] [거절] 버튼** → 누르면 답장 툿 자동 작성 |
     | 젤리빈 | 봉지 그림 + 남은 젤리빈 수, 이번 턴 먹은 맛 칩, 다음 차례 |
     | 곱스톤 | 라운드 진행 막대, 이번 투구(강도·명중), 점수판 |
     | 마법결투 | 두 마법사 카드(HP 하트), 가운데 두 주문 대결(상성 화살표), 필살기 표시 |
     | 물약 | 솥 그림, 재료 9개 칩, 턴별 (정답 ● / 순서 틀림 ○) 표 — 정답 재료는 끝난 뒤에만 |
     | 퀴디치 | 경기장 점수판, 이번 턴 행동 아이콘(쿼플·블러저·스니치), 스니치 확률 |
     | 수업 | 과목 헤더, 등급 메달(O·E·A…), 수업이면 순위표, 레비오사는 반응 시간 막대 |
     | 토너먼트 | 경기 시작·우승 카드 (대진표 칸 미니 표시) |
     | 점수 지급 | 소속 문장 + "+10" 금빛 숫자 |
   - (웹) 내 차례면 카드에 행동 버튼: 젤리빈 [먹기], 곱스톤 [약][중][강] → 답장 툿 작성. 비밀 선택(결투·물약·퀴디치·비행)은 버튼이 **DM** 으로 보낸다.

3. **컨텐츠 진행 화면** (선택)
   - `/system/sessions/:id` 한 판 전체를 한 화면에 (스레드 대신). 시스템 메뉴의 진행 중 컨텐츠·대진표 칸에서 이 화면으로 이동.
   - 30초 갱신 또는 스트리밍(나중).

4. 확인: 낮/밤 테마, 폰 브라우저 폭, 앱(텍스트 그대로)

### ①-2 관리 화면(컨텐츠 설정·캐릭터 명단·토너먼트) UI 대폭 개선 ← **1차 완료 (2026-10-14)**

> 된 것: 1·2·3·4번 대부분, 5번(카드·소속 칩·한꺼번에 바꾸기). 남은 것: 확률 합계 100% 막대, 칩 끌어서 순서 바꾸기, 개인 값 표 편집, 6번 토너먼트 브래킷 편집.

**요청**: 설정 화면을 보기 편하게, 시각적으로 크게 바꾼다. 지금은 입력칸이 길게 나열돼 있어 찾기·이해하기 어렵다.

1. **컨텐츠 설정 첫 화면 = 카드 목록**
   - 컨텐츠·수업 과목마다 카드 (아이콘/그림, 이름, 켜짐 스위치, 시작 명령어, 최근 1주 판 수). 누르면 그 컨텐츠 설정으로.
   - 탭 줄(공통·토너먼트·소속·수업 공통·컨텐츠 9개)이 너무 길다 → 왼쪽 세로 목록(분류: 공통 / 1:1 대결 / 마법 수업 / 이벤트) 또는 카드 목록으로.
2. **설정 화면 구조**
   - 묶음(기본·명령어·규칙·확률·문구)을 접었다 펴는 카드로. 바뀐 값이 있는 항목엔 '변경됨' 표시 + 항목별 **기본값으로 되돌리기**.
   - 확률·점수는 숫자칸 대신 슬라이더/표 (예: 곱스톤 약·중·강 × 명중률·점수, 변신술 약·중·강 × 완벽·어중간·실패 합계 100% 막대).
   - 위쪽에 이 컨텐츠 한 줄 설명 + "이렇게 진행돼요" 미니 흐름도 (신청 → 수락 → DM 선택 → 결과).
   - 저장 버튼은 화면 아래에 고정(스티키) + 저장 안 한 변경 알림.
3. **문구 편집기**
   - 오른쪽에 **실시간 미리보기**: 툿 모양 카드(시스템 아바타·이름) 안에 견본 이름(해리·드레이코)으로 채운 결과, `{계정 아바타}` 면 사진 자리까지.
   - 명령어 버튼을 종류별 색으로 (사람 / 값 / 조사), 문구별로 쓸 수 있는 것만. 모르는 `{명령어}` 는 빨간 밑줄 경고.
   - 문구가 많은 컨텐츠는 "자주 바꾸는 문구"만 먼저 보이고 나머지는 접기.
4. **목록형 데이터**: 젤리빈 맛·변신술 과제·비행 경로·수호령 등 줄마다 입력 → 칩 목록(추가·삭제·끌어서 순서) 으로.
5. **캐릭터 명단**: 소속 문장·아바타가 있는 카드/표, 소속별 필터 칩, 여러 명 선택해 소속 한꺼번에 바꾸기, 개인 값(스탯) 표 편집.
6. **토너먼트**: 대진표를 실제 브래킷 선 연결 모양으로, 칸 클릭 → 옆 패널에서 컨텐츠·시간·선수 편집, 선수는 드래그로 배치.
7. 디자인: 웹 시스템 화면과 같은 톤(양피지·금박·명조 제목)을 관리 화면에도 살짝 — 단 입력칸은 읽기 쉽게. 낮/밤 테마·좁은 화면 확인.
8. 구현 메모: 지금은 HAML + 약간의 JS. 미리보기·칩 목록·슬라이더가 많아지면 컨텐츠 설정 화면만 React 컴포넌트(관리 화면의 `data-admin-component` 방식, `app/javascript/mastodon/components/admin/`)로 만드는 게 낫다. 저장 API 는 지금 `PATCH /admin/games/:key` 그대로 써도 됨.

### ② 비밀의방 (마피아형 서버 이벤트) ← **완료** (`Game::Events::SecretChamber`)

- `[비밀의방]` → 참가 모집(시간 설정) → `[참가]` → 마감 때 역할 DM (배신자 ≈1/4, 오러, 치유사, 예언자, 학생)
- 낮(예: 20~22시) 공개 토론 + `[고발] @누구` 투표 → 최다 득표 퇴학(진영 공개), 밤에 역할 DM 행동
  (배신자: 함께 상의해 석화 / 오러: 조사 / 치유사: 보호, 같은 사람 연속 불가 / 예언자: 모호한 예언)
- 배신자끼리 그룹 DM (`DmRoom` 그룹 기능 사용 가능, 최대 20명)
- 승리: 호그와트 = 배신자 전원 퇴학, 어둠 = 배신자 수 ≥ 남은 호그와트 수. 승리 진영 전원 +15, 생존 +5
- 이름(비밀의방/배신자 등)·역할·인원 비율·페이즈 시간·예언 문구 전부 설정으로
- 웹: 생존자 명단, 투표 현황, 탈락자 진영, 내 역할 카드, (예언자) 예언 노트
- 구현 메모: 여러 날 진행 → `Game::TimeoutWorker` 로 페이즈 전환 예약 (낮 시작/끝, 밤 끝). 세션 1개에 players N명, state 에 역할·생존·투표.

### ④ 정기 툿 ← **완료** (`Game::Summary`, `Game::WeeklySummaryWorker` 매시 확인, 관리 > 캐릭터 명단 > 소속 탭의 버튼)

- 매주 일요일 밤 주간 결산 툿 (소속 점수 변화, 이번 주 최다 승리 등) — Sidekiq 스케줄러(`config/sidekiq.yml` 의 scheduler)에 작업 추가
- 학기 말: 과목별 수석(성적표 O 개수 → 평균), 우승 소속 발표 — 관리 화면에 '학기 마감' 버튼
- 같은 상대 하루 3판 제한 등은 이미 있음

### ④-2 캐릭터 명단 (관리 > 시스템 > 캐릭터 명단) ← **완료**

- 탭: 명단 / 항목 설정(`/admin/characters/fields`) / 소속(예전 컨텐츠 설정의 기숙사 탭, `/admin/characters/houses`, 옛 주소는 redirect).
- `GameCharacterField`: 이름·종류(select/text/number)·구분(profile 정보 / stat 전투 스탯)·고를 값(이름|#색). 처음에 진영(불사조 기사단·죽음을 먹는 자들)과 체력·공격·방어.
  정보 값은 `game_characters.profile` 에 항목 id 로, 전투 스탯은 `stats` 에 이름으로 (스탯 항목 이름을 바꾸면 값도 옮김).
- `game_characters.money` (단위 이름은 공통 설정 `currency_name`, 기본 갈레온), `inventory` = [{ name, count, note }].
- 보상: 각 컨텐츠 설정의 '보상 (돈·아이템)' 묶음, 아이템 줄은 `이름|개수|확률%`. 결과 툿 아래 `💰 … 보상: 10 갈레온, 초콜릿 개구리` + 카드에 보상 줄. 캐릭터 편집 화면에 최근 받은 보상.
- 다음 후보: 서버원 상점/선물(자동봇 시트 상점과 겹치지 않게 정할 것), 전투 컨텐츠에서 스탯 쓰기.

### ⑤ 나중에 / 보류

- 모의 전투(카드게임형, 학생 기간) / 전투(성인 기간, 명칭만 다름) — 별도 설계 필요
- 마법사 체스 — 보류 (간편 룰 필요)
- 물약 확장: 교수 계정이 수업으로 열면 전원 참가, 먼저 맞힌 상위 3명 점수
- 퀴디치 확장: n:n, 캐릭터 포지션·스탯 (캐릭터 명단의 '개인 값' 활용)

## 3. 지켜 온 결정 (요약)

- 엔진은 마스토돈 안 (Python 자동봇 아님). 게임 데이터는 DB, 자동봇(ssbot)의 시트는 상점·키워드 등 기존 기능만.
- 공개 범위: 서버원 툿은 팔로워 공개가 기본(전원 서로 팔로우). 신청 툿이 DM 이면 진행도 DM.
- 시스템 답장은 **방금 명령어를 보낸 툿**에 단다 → 한 스레드. DM 으로 보낸 비밀 선택은 공개 스레드에 끼우지 않는다.
- 모르는 [명령어]는 조용히 넘긴다 (자동봇과 겹치지 않게).
- 모든 명령어·시간·확률·점수·문구는 관리 화면에서 바꿀 수 있게 (`Game::Config` 항목 정의 + 바뀐 값만 저장).
- 토너먼트: 대진표는 사람, 이긴 경기 수가 가장 많은 소속 우승(동률 → 결승 승자 소속), 시간 초과·무승부는 운영진 판정
  (단, 시간 초과가 규칙인 컨텐츠 — 곱스톤·결투·물약·퀴디치 — 는 그대로 진행).
- 소속 이름은 설정 (학생 기간 '기숙사', 성인 기간 '진영').

## 4. 집 PC에서 이어 하기

```bash
git clone https://ud0ng@github.com/ud0ng/ssmastodon.git   # 이미 있으면 git pull
bash dev/preview/setup.sh                                  # 처음 한 번 (빌드 10분쯤)
```

- 미리보기: http://127.0.0.1:8080 , 관리자 owner@preview.test (비밀번호 `dev/preview/.owner_password`)
- `setup.sh` 가 컨텐츠 시험용 계정(@system, luna, draco, cedric)과 기본 소속·캐릭터 명단을 만들어 둔다. `rebuild` 는 DB 마이그레이션도 한다.
- 이미 예전 미리보기가 있는 PC 면 `git pull` 뒤 `bash dev/preview/setup.sh rebuild` 한 번이면 된다.
- 툿 흉내: `PostStatusService.new.call(Account.find_local("owner"), text: "@system @luna [결투]", visibility: "private")` (sidekiq 이 처리)
- 테스트: `CLAUDE.md` 의 Ruby 테스트 명령 + `spec/lib/game spec/requests/api/v1/system_spec.rb`
- 이 PC 메모: 저장소가 OneDrive 안이면 `setup.sh` 가 OneDrive 밖으로 복사해서 빌드한다. Docker Desktop 이 멈추면 재시작 (`wsl --shutdown` 뒤 Docker Desktop 실행).
- 서버 반영: `cd ~/mastodon && git pull && docker compose build && docker compose up -d` (마이그레이션 자동)
