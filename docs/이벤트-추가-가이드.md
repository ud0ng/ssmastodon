# 새 이벤트 추가하기 (웹 전용 이벤트 가이드)

새 이벤트를 만들 때 이 문서를 먼저 읽는다. 기준 구현은 **덤블도어의 군대**(`Game::Web::DumbledoresArmy`, 가장 단순한 단계형)이고,
더 복잡한 예는 비밀의 방(역할·밤낮), 도둑 지도(팀·지도), 미로(동시 이동), 비행 대결(동시 선택)이다.

이벤트는 **공통 컴포넌트를 그대로 쓴다.** 새로 만드는 것은 규칙(서버 클래스)과 판 화면(무대 컴포넌트) 둘뿐이다.

| 공통으로 되는 것 | 어디서 |
|---|---|
| 모집(운영진 [이벤트 열기]·초대하기·테스트 플레이), 참가·정원·하루 제한·알림 배지 | `Game::Events::Recruiting`, `Game::Events::Opening`, 이벤트 설정 |
| 대기실(준비·채팅·카운트다운·초대·인원 부족 취소·모달 안내) | `Game::Lobby`, `features/system/lobby.tsx` — 새로 만들지 않는다 |
| 규칙 화면(컨텐츠 > 이벤트 > 규칙 탭, 대기실·게임방 도움말) | `Game::Guide::TEXT` |
| 점수·재화·아이템 보상, 하루 보상 횟수, 판수제, 토너먼트 기간, 전적 | `finish!` (아래 보상 참고) |
| 이벤트 설정(관리 > 시스템 > 이벤트 설정 > 목록, 컨텐츠 설정의 항목·문구) | `FIELDS` 만 정의하면 화면이 저절로 만든다 |
| 채팅(전체 · 팀 채팅), 다시 보기, 관전(운영진은 비밀까지) | `Game::Lobby.chat!`, `team_of`, `can_chat?`, `spectatable?` |

## 1. 서버 클래스 (`app/lib/game/web/<이벤트>.rb`)

`Game::Kinds::Base` 를 상속하고 `include Game::Events::Recruiting` 를 한다. 처음에는 덤블도어의 군대 파일을 통째로 복사해 고치는 게 가장 빠르다.

필수:

- `KEY`, `FIELDS = (base_fields(name:, command:, points_win:) + [...] + Game::Events::Recruiting.fields(min:, max:)).freeze`
  - 항목마다 `group:` 을 준다: `rules`(규칙) / `time`(시간) / `roles`(이름) / `commands`(명령어) / `messages`(문구). 화면이 이 묶음대로 보여 준다.
  - 모든 규칙·시간·이름·문구는 FIELDS 로 빼서 **이벤트 설정에서 고칠 수 있게** 한다. 코드에 숫자나 문구를 박지 않는다.
- 클래스 메서드: `web?`(true), `event_only?`(true), `spectatable?`(true), `continues_on_timeout?`(true), `max_opponents`, `invite_error`, `chat_keep`
- `start!`: 역할·상태를 `state` 에 넣고 `session.update!(turn: 1)`, 시작 안내 `post(...)`, 첫 단계 시작
- `handle(player, command, args, _status)`: 웹이 보낸 명령어. `config['cmd_...']` 와 비교해 처리하고 모르는 명령어는 `false`
- `timeout!`: **단계 시간이 끝났을 때** 어떻게 넘어갈지 (고르지 않은 사람은 기본값으로 채워서 판이 멈추지 않게)
- `view_for(player, staff: false)`: 화면이 읽는 상태. 이 사람에게 **보여도 되는 것만** 담는다 (비밀은 서버에서 거른다). `player` 가 nil 이면 관전
- `card_data`, `card_actions`(보통 `[]`), `pending_seats`, `max_turns`
- 탈락이 없는 이벤트는 `forfeit!` 을 비운다

쓰는 도구:

- 단계 시간: `Game::Engine.set_deadline_in!(session, 초)` → 끝나면 `timeout!` 이 불린다. 클라이언트가 시간을 재서 서버를 두드리게 하지 않는다.
- 공개 안내: `post(text)`(웹 메시지), 한 사람에게만: `dm(player, text)`. 툿은 올라가지 않는다 (모집 툿만 툿).
- 비밀 정보(역할·카드)는 `state` 에 넣고, `view_for` 에서 사람마다 거른다.
- 팀 채팅이 필요하면 `team_of(player)` 가 팀 이름(없으면 nil)을 돌려준다.
- 비밀 역할을 운영진이 대기실에서 정하게 하려면 `lobby_roles?` (비밀의 방 참고), 팀을 대기실에서 나누려면 `lobby_teams?` (도둑 지도 참고).

등록 (3곳):

1. `app/lib/game/kinds.rb` 의 `registry` 에 한 줄
2. `app/lib/game/guide.rb` 의 `TEXT` 에 규칙 화면 내용 (`summary`, `cast`(역할 소개), `rules`(표 포함), `roles`(승리 조건), `items`, `steps`). `%{항목}` 은 FIELDS 값으로 채워진다.
3. `app/helpers/admin/game_helper.rb` 의 `GAME_ICONS` 에 이모지

## 2. 보상 — 반드시 공통 `finish!` 로

끝낼 때 `finish!(winners: 이긴 사람들, message: 결과 안내)` (비기면 `draw: true`) 만 부른다. 점수·재화·아이템 지급, 하루 보상 횟수 제한, 판수제, 토너먼트 기간,
전적, 테스트 플레이 처리가 한꺼번에 된다. **직접 `Game::Points`/`Game::Rewards` 를 부르지 않는다.**

- 테스트 플레이(`session.test?`)는 점수·보상·전적이 **없어야 한다.** `finish!` 가 막아 주니 우회하지 않는다. 스펙에 꼭 넣는다.
- 이긴 쪽이 한 팀 전체면 `winners:` 에 그 팀을 모두 넣는다.

## 3. 웹 화면 (`app/javascript/mastodon/features/system/<이벤트>_stage.tsx`)

- 기준: `army_stage.tsx`. props 는 `{ sessionId, name, chat, staff, isPlayer, onChanged }`.
- **읽기**: `v1/system/sessions/:id/view` 를 `REFRESH_MS = 2_500` 마다. 줄이지 않는다. 행동은 `sendCommand({ session_id, command, args })`.
- 등록: `session.tsx` 에 (1) `EVENT_KINDS` 에 키 추가, (2) `<이벤트>Room` 변수와 갱신 간격 조건, (3) `<Stage ... />` 렌더, (4) `!armyRoom` 같은 조건 목록. 대기실은 건드리지 않는다.
- 스타일: `styles/mastodon/_game_<이벤트>.scss`(클래스 접두사 2~3글자, 예 `da-`)를 만들고 `styles/application.scss` 에 `@use`.
- 서버 시계: 남은 시간은 `view.now` 와 `deadline_at` 으로 센다 (내 컴퓨터 시계가 달라도 같게).

### 연출 원칙 (웹게임 느낌)

- **framer-motion** 으로 단계마다 눈에 띄게: 등장(`initial/animate`), 뒤집히는 카드(`rotateY`), 끌어다 놓기(`drag` + `dragSnapToOrigin`), 도장 쿵(`scale 3 → 1`), 순서대로 공개(`delay: index * …`), 반짝이 입자(`Sparks`).
- 오프닝(`Opening`): 방 문이 열리는 연출 → 내 역할 카드가 뒤집힘. `sessionStorage` 로 한 판에 한 번만.
- 공개는 서버가 한꺼번에 주고, **화면이 한 장씩 보여 준다** (서버 부하 없이 긴장감). 비밀이 새지 않게 순서는 섞어서 준다.
- **효과음은 Web Audio 로 직접 만든다**(파일 없음, `tone`/`noise`/`sfx` 객체). 소리 켜기/끄기 버튼과 `localStorage` 키(`ssm:<접두사>-sound`)를 둔다.
- **배경 음악**은 파일만 넣으면 되게 해 둔다: `public/sounds/<kind key>_bgm.mp3`, `BGM_URL`/`BGM_VOLUME`, 파일이 없으면 조용히 건너뛰고 한 번 누르면 시작(자동 재생 차단 대응). 파일을 받으면 저작권 출처를 이 폴더에 적는다.
- 라이브러리·폰트는 필요하면 받아도 된다. 아이콘 그림은 CC 라이선스면 출처를 파일 맨 위에 적는다 (`maze_art.ts` 참고).

## 4. 서버 부하 규칙 (20명 동시 접속에서 502 났던 일, CLAUDE.md 참고)

- **계산은 단계가 바뀔 때만**: 모두 냈을 때 / `timeout!`. 화면이 읽을 때마다 계산하지 않는다 (`view_for` 는 `state` 를 거르기만).
- `view_for` 에 큰 배열을 넣지 않는다. 지난 일은 `results`/`history` 처럼 작게, 최근 N개만(`log.last(40)`).
- 사람마다 조회(N+1) 금지. 컨트롤러가 참가자 계정·캐릭터를 미리 읽어 두니 `players` 만 쓴다 (`Game::Lobby.preload_characters`).
- 폴링으로 시간을 재지 않는다 → `set_deadline_in!` + `timeout!`.
- 비밀 제출은 `session.with_lock`(`Game::WebCommand.play`) 안에서 `state` 에 넣고 저장만 한다.

## 5. 테스트 (꼭)

- 규칙 스펙 `spec/lib/game/<이벤트>_spec.rb` — `dumbledores_army_spec.rb` 를 본뜬다: 인원별 구성, 명령어, 단계 넘김(`timeout!`), 비밀 정보 가림(`view_for`), 끝, **점수·보상 지급**, **테스트 플레이는 없음**.
- 공통 스펙에 종류 추가: `spec/lib/game/recruiting_events_spec.rb` 의 종류 배열, `spec/requests/api/v1/system/games_spec.rb` 의 그룹 목록.
- 미리보기(`bash dev/preview/setup.sh rebuild`)로 장면마다 캡처해서 본다. 판 하나 만들기: 대기실 세션 → `Game::Lobby.start!(session)` (`dev/preview/da_demo.tmp.rb` 참고).
